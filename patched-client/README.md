# Celeritas 1.8.9 patched client

Builds a **patched `client.jar`**, not a Java agent. Celeritas' 1.8.9 mixins,
Phosphor's lighting engine and Tessera's LWJGL3 shim/rewriter are applied to the
decompressed Minecraft classes at build time; the output has no `Premain-Class`,
no Mixin and no ASM on its runtime class path.

## Build

```sh
./gradlew :patched-client:assemble
```

That is the whole pipeline. It

1. fetches `version_manifest_v2.json`, the 1.8.9 version JSON, its `client.jar`
   and library artifacts from Mojang into `patched-client/build/base/` and
   verifies their SHA-1;
2. remaps that client to the names the sources are written in, so they can be
   compiled against:
   - `src/celeritas` is written in Ornithe Feather names, so the client goes
     `official -> intermediary -> named` with `calamus-intermediary` + `feather`;
   - `src/phosphor` is written in Legacy Fabric Yarn names, so the client also
     goes `official -> intermediary -> named` with Legacy Fabric's
     `intermediary` + `yarn` (a separate chain, both end up at the official
     client at runtime);
3. compiles both source sets (`src/phosphor` is vendored upstream code, see
   `src/phosphor/README.md`), plus `:common`;
4. remaps the compiled classes back (`named -> intermediary -> official`) with
   tiny-remapper, including Mixin's annotation strings and `@Accessor` targets;
5. runs the offline patcher, which applies both mixin configs and the LWJGL3
   rewriter, and writes the jars below.

No mod loader, Loom or mod jar is involved: the only thing produced is the
client jar and its patch.

The patch is generated by the small Rust tool in `patch-tool/`, using the
normalized `client-base.jar` as its base. `:patched-client:generatePatch` can be
run on its own.

The output must precede the ordinary game libraries on the class path: a few
third-party classes that call LWJGL2 (currently paulscode's OpenAL wrapper) are
rewritten and copied into the jar so they win over the original library jars.
`patched-client/run-test.sh` does this and launches without `-javaagent`.

Mixin, ASM and tiny-remapper are build-time dependencies only and are filtered
out of the output. MixinExtras is build-time too, except for the handful of
runtime classes the patched classes still reference (see below).

## What it does

- Compiles the Celeritas and Phosphor sources against named client jars and
  remaps the result to official names, so no refmap and no mod loader are needed.
- Applies `mixins.celeritas.client.json` (Sodium-style renderer) and
  `phosphor.mixins.json` (lighting engine) to the vanilla classes with Mixin.
- Runs Tessera's LWJGL3 rewriter over the patched game classes, Celeritas'
  classes, and library classes that still use LWJGL2.
- Replaces Mixin's `CallbackInfo`/`CallbackInfoReturnable` references with the
  tiny `org.taumc.celeritas.patch` shims, so the result needs no Mixin runtime.
- Merges Celeritas, Tessera's LWJGL3 shim and the generated `@Local`
  implementations.
- Copies only the MixinExtras classes the patched classes can actually reach
  (currently `LocalBooleanRef`, its generated implementation and
  `LocalRefRuntime`). The injectors, the expression parser, the annotation
  processor and the transformer extensions are build time only, so the whole
  runtime is not shipped. The walk follows constant-pool references from every
  written class, and the patcher refuses to write an output that still mentions
  a MixinExtras class it did not copy.
- Drops `META-INF/*.SF`, `*.RSA`, `*.DSA`, `*.EC` and `Sealed:` lines, and emits
  deterministic entry timestamps.
- Pins the parts of Mixin's output that vary per run: the random
  `@MixinMerged.sessionId` and the `md<uid>$…`/`fd<uid>$…` names of generated
  members (the uid is the order in which target classes asked for one) are
  replaced with declaration-order names. Added entries are also written in
  sorted order, so the jar does not inherit the (unstable) entry order of the
  remapped Celeritas jar. Two builds of the same inputs are therefore byte
  identical, which is what keeps Tessera's AOT cache valid.

fastutil is provided by Tessera: its installer adds the same
`it.unimi.dsi:fastutil:8.5.18` artifact the client needs.
The patched client itself stays small; fastutil is a normal library on the game
class path.

## AOT

The jar is patched before launch, so no class is transformed at runtime. The
result is eligible for Tessera's 1.8.9 AOT cache, unlike the old agent-based
target.

## Test result

Launched against Tessera's 1.8.9 `mdtLwjgl3` installation on Java 28 EA without
an agent:

```
LWJGL Version: 2.9.4 (LWJGL3 shim)
[tessera-lwjgl3] Display.create ok 854x480
OpenAL initialized.
Sound engine started
Created: 512x512 textures-atlas
```

F3 shows `Celeritas Renderer (2.5.0-patch)`.
